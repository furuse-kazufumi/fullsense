# 箸で豆を6秒挟めたのに、持ち上げた瞬間に落とす — 筋肉でできた手に、正直に食べさせようとした話

> 対象: ロボット操作・筋骨格シミュレーション・「正直な計測」に興味がある人。前提知識は Python が読めれば十分で、力学と制御の用語は都度かみくだきます。
> 数値はすべて自宅 PC のローカル実測です。**私**が方向を決めて映像を目で確かめ、実装と実験は **AI** が回しました。この記事の「あなた」は、読んでいる**あなた**だけを指します。
> これは成功譚ではありません。**掴めたのに運べない**、という一つの壁に、何度も別の顔で殴られ続けた記録です。

---

## 0. 3行まとめ(先に結論)

- 動機は **「手を失った人の AI 義手(prosthetic hand)や、介護の配膳ロボットが、箸で食事を掴んで口へ運べるか」**。前回は箸の形をしたトイ(手が無い)で測ったので、今回は **筋肉で動く本物の手** ——**MyoHand**(23 自由度・39 筋)と、全身骨格 **evis**(81 筋の右手 + 動く腕 + 頭)——に、正しい持ち方で 2 本の箸を持たせた。
- **持つ**ことはできた。親指の先と人差し指の先の**二点でつまむ**正しい形になり、そっと揺すっても落とさない。しかも**筋肉を全部 OFF にすると 1.5 m 落下する**——つまり幾何のインチキではなく、本当に筋肉で握っている(この確かめ方が本記事の背骨)。ところが **持ち上げて運ぼうと動き出した瞬間に、握りが崩れて落とす**。
- **「掴める」と「運べる」は別物だった。** そして道中の「成功」の多くは、あとで見ると**楔(くさび)で挟まっていただけ**・**食べ物の自重を握力と読み違えていただけ**・**握った瞬間に横へ射出していただけ**だった。この記事の価値はタスクの新しさ(箸把持は既出)ではなく、**その嘘を一つずつ剥がした測り方**にある。

## 1. 用語(先に地図)

先に地図を配ります。知っている人は飛ばして構いません。

| 用語 | かみくだき |
|---|---|
| 筋骨格モデル(musculoskeletal model) | モータではなく**筋肉の収縮**で関節を動かすシミュレーション。人体に近いぶん、制御は格段に難しい |
| 把持(grasp / grasping) | 物を「掴む」こと。ここでは 2 本の箸で挟む |
| force-closure(力の閉じ・把持の安定条件) | 物体をどの向きに押しても、指や箸が押し返せる状態。これが本当の「掴めている」。品質は ε(イプシロン)という数値で測る |
| ablation(切除テスト) | **筋肉を全部 OFF にして、物が落ちるかを見る**。落ちれば「筋肉で握っていた」証拠。落ちなければ、ただ幾何的に挟まっていただけ |
| 楔 artifact(wedge artifact) | 指の隙間に物が**幾何的にはまり込んでいるだけ**なのを「握れた」と誤読すること。ablation で暴ける |
| 母指対向(thumb opposition) | 親指の腹を、他の指へ向かい合わせること。これが無いと箸のような精密つまみは**原理的に不可能** |
| condim(接触の自由度) | MuJoCo で接触が持つ次元。3 だと滑り摩擦だけ、6 だと**ねじれ・転がり摩擦も**扱う。丸い箸の上で物がくるっと回って逃げるのを止めるのに要る |
| held-out(訓練外テスト) | 学習に一切使っていない設定での成績。**汎化**(未知への強さ)の唯一の証拠 |
| 窓積分(windowed impulse) | 一瞬の接触力ではなく、一定時間で**均した**力。ソルバのノイズのスパイクを「成果」と偽らないための衛生 |
| 射出(ejection) | 上下から圧迫された物が、横の拘束が無いために飛び出す現象。石鹸を握ると滑って飛ぶのと同じ |
| 共進化(co-adaptation) | 持ち方と運搬動作を同時に最適化すると、片方が犠牲になる問題。この記事の壁の正体 |

> ここまでが地図です。次の章から、なぜ「本物の手」でやり直したのか、そして最初にぶつかった「手そのものの罠」から順にたどります。
