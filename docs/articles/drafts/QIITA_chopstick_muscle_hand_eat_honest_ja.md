# 箸で豆を6秒挟めたのに、持ち上げた瞬間に落とす — 筋肉でできた手に、正直に食べさせようとした話

> 対象: ロボット操作・筋骨格シミュレーション・「正直な計測」に興味がある人。前提知識は Python が読めれば十分で、力学と制御の用語は都度かみくだきます。
> 数値はすべて自宅 PC のローカル実測です。**私**が方向を決めて映像を目で確かめ、実装と実験は **AI** が回しました。この記事の「あなた」は、読んでいる**あなた**だけを指します。
> これは成功譚ではありません。**掴めたのに運べない**、という一つの壁に、何度も別の顔で殴られ続けた記録です。

---

## 0. 3行まとめ(先に結論)

- 動機は **「手を失った人の AI 義手(prosthetic hand)や、介護の配膳ロボットが、箸で食事を掴んで口へ運べるか」**。前回は箸の形をしたトイ(手が無い)で測ったので、今回は **筋肉で動く本物の手** ——**MyoHand**(23 自由度・39 筋)と、全身骨格 **evis**(81 筋の右手 + 動く腕 + 頭)——に、正しい持ち方で 2 本の箸を持たせた。
- **持つ**ことはできた。親指の先と人差し指の先の**二点でつまむ**正しい形になり、そっと揺すっても落とさない。しかも**筋肉を全部 OFF にすると 1.5 m 落下する**——つまり幾何のインチキではなく、本当に筋肉で握っている(この確かめ方が本記事の背骨)。ところが **持ち上げて運ぼうと動き出した瞬間に、握りが崩れて落とす**。
- **「掴める」と「運べる」は別物だった。** そして道中の「成功」の多くは、あとで見ると**楔(くさび)で挟まっていただけ**・**食べ物の自重を握力と読み違えていただけ**・**握った瞬間に横へ射出していただけ**だった。この記事の価値はタスクの新しさ(箸把持は既出)ではなく、**その嘘を一つずつ剥がした測り方**にある。

## 1. 用語(先に地図)

先に地図を配ります。知っている人は飛ばして構いません。

| 用語 | かみくだき |
|---|---|
| 筋骨格モデル(musculoskeletal model) | モータではなく**筋肉の収縮**で関節を動かすシミュレーション。人体に近いぶん、制御は格段に難しい |
| 把持(grasp / grasping) | 物を「掴む」こと。ここでは 2 本の箸で挟む |
| force-closure(力の閉じ・把持の安定条件) | 物体をどの向きに押しても、指や箸が押し返せる状態。これが本当の「掴めている」。品質は ε(イプシロン)という数値で測る |
| ablation(切除テスト) | **筋肉を全部 OFF にして、物が落ちるかを見る**。落ちれば「筋肉で握っていた」証拠。落ちなければ、ただ幾何的に挟まっていただけ |
| 楔 artifact(wedge artifact) | 指の隙間に物が**幾何的にはまり込んでいるだけ**なのを「握れた」と誤読すること。ablation で暴ける |
| 母指対向(thumb opposition) | 親指の腹を、他の指へ向かい合わせること。これが無いと箸のような精密つまみは**原理的に不可能** |
| condim(接触の自由度) | MuJoCo で接触が持つ次元。3 だと滑り摩擦だけ、6 だと**ねじれ・転がり摩擦も**扱う。丸い箸の上で物がくるっと回って逃げるのを止めるのに要る |
| held-out(訓練外テスト) | 学習に一切使っていない設定での成績。**汎化**(未知への強さ)の唯一の証拠 |
| 窓積分(windowed impulse) | 一瞬の接触力ではなく、一定時間で**均した**力。ソルバのノイズのスパイクを「成果」と偽らないための衛生 |
| 射出(ejection) | 上下から圧迫された物が、横の拘束が無いために飛び出す現象。石鹸を握ると滑って飛ぶのと同じ |
| 共進化(co-adaptation) | 持ち方と運搬動作を同時に最適化すると、片方が犠牲になる問題。この記事の壁の正体 |

> ここまでが地図です。次の章から、なぜ「本物の手」でやり直したのか、そして最初にぶつかった「手そのものの罠」から順にたどります。

## 2. なぜ「筋肉の手」で、なぜ食事なのか

<!-- SURVEY 反映待ち: 関連研究(UW Grasping with Chopsticks ICRA2021 / CherryBot 2023 / Yang et al. SIGGRAPH2022 arXiv:2205.14313 / assistive feeding: Srinivasa lab ADA / MyoSuite・musclemimic)。background workflow wbwfn3a3d の synthesis を反映して確定。 -->

動機は最初から一つでした。**手を失った人の AI 義手や、介護の配膳ロボットが、箸で食事を掴んで口へ運べるか。** 箸は、フォークのように刺すのでも、スプーンのようにすくうのでもなく、**2 本の棒で挟む**——最も繊細で、最も日本的な道具です。もしこれが手の中で成り立つなら、応用の幅は広い。

前回、私はこの問いを**箸の形をしたトイ**で測りました(前日譚の記事)。だがそのトイには**手が無かった**——箸を直接プログラムで動かしていただけです。だから宿題が残りました。「本物の手で、筋肉で、箸を持てるのか」。今回はそこに答えます。使うのは 2 つのシミュレーションの手です。

- **MyoHand** — 23 自由度・39 本の筋でできた手だけのモデル。指の細かな動きを詰めるのに向く。
- **evis** — MS-Human-700 という全身骨格の右手(48 関節・81 本の筋)に、動く腕と頭を繋いだモデル。**皿から口まで**を一気通貫で試せる。

そして先に正直な地図を配ると、**タスクそのものはもう新しくありません**。ワシントン大学の一連の研究(*Grasping with Chopsticks*, ICRA 2021 ほか)は実機の箸で小物を掴むところまで行き、Yang らの *Learning to Use Chopsticks in Diverse Gripping Styles*(SIGGRAPH 2022)は、**物理シミュレーションの人型の手が箸で多様な持ち方を自動発見して物を運ぶ**ところまで到達しています。だから私が新しさを主張できるのは、掴めたかどうか**ではありません**。主張できるのは一点——**「掴めた」という嘘を、筋肉を切って(ablation)、映像を見て、段階に分けて、どこまで剥がせるか**。この記事はその剥がし方の記録です。

> 教訓の先取り: 調べると、しばしば「自分の面白い案」は誰かがやっている。落胆ではなく、**どこが本当に空いているか**を教えてくれる地図だと思えばいい。空いていたのは「正直さ」の側でした。

## 3. 手そのものの罠 — 親指が、指に届かない

最初の壁は、制御でも学習でもありませんでした。**手の骨格そのもの**です。

evis の手を初めて見たとき、私は「指の動く関節がゼロの、ミトンのような固まりだ」と思い込みました。これが最初の誤診です。よく調べると、evis の Manipulation シーンの手は、最初から **38 本の筋で動く、関節化された 5 本指**でした(母指の対立筋も含む)。「指が動かない」は、私が別の(移動用の)モデルの手を見て一般化した勘違いでした。**AI が実装を進め、私が映像で確かめる**——この体制で、私の思い込みが一つ剝がれました。

だが、もっと深い真実がその下にありました。指は動く。なのに、**親指が他の指に届かない**のです。

箸のような精密なつまみには、**母指対向(thumb opposition)**——親指の腹を他の指へ向かい合わせる動き——が要ります。ところが evis の母指は、対立筋を最大まで働かせても、指先まで **約 1.8 cm** の隙間が残る(`opt_thumb.py` が親指先と指の中節の距離を実測)。箸の棒の半径はせいぜい 0.3 cm。**1.8 cm の谷は、0.3 cm の棒では埋められない**。だから、どんなに筋肉を鍛えても、どんな姿勢を探索しても、この手では箸を挟めない。全実験で「筋肉の有無によらず結果が同じ(物が常に落ちる)」だったのは、これが理由でした——**筋肉の問題ですらなく、骨の問題だった**。

私はここで、あなたの直感が正しかったことを認めます。あなた——読者としてこの設計を追ってきた人——ではなく、これは**私自身が過去に下した「手術など要らない」という判断への訂正**です。AI が骨格を一次調査して、母指の分節を **1.6 倍に延長**する「手術」を施すと、親指先が指に **約 0.5 cm** まで届き、**初めて対向が成立**しました。把持の最良スコアも大きく改善した。手の中に、ようやく「挟む顎」ができたのです。

正直な但し書きを 1 つ。これは**シミュレーションのトイ**であって、動く義手ではありません。しかも母指を 1.6 倍に延ばす「手術」は、**現実の手には無い改造**です。私がやっているのは「介護義手が箸で食べる」という動機を、制御の問いに落とし込む最小の舞台づくりであって、明日の義手そのものではない——ここを混同しないよう、先に釘を刺しておきます。

![親指の姿勢——修正の前と後。「親指の曲がり方に違和感がある」という一言が出発点だった。持ち方そのものを数値にして直した(scripted・held=成功)](https://raw.githubusercontent.com/furuse-kazufumi/fullsense/main/docs/articles/assets/hillco_walk/chop1_thumb_compare.gif?v=1)

> ここまでで分かったこと: **「掴めない」の原因は、制御より前に、骨格にあることがある**。上の層(学習)をいくらいじっても、下の層(解剖)が塞がっていれば永遠に解けない。まず手を測る。

## 4. 楔(くさび)の罠 — 「持てた」を、筋肉を切って確かめる

手術で顎ができた。次は「握れたか」を測る番です。そしてここで、この記事でいちばん大事な道具が出てきます——**ablation(切除テスト)**。

やり方は乱暴なくらい単純です。**握っている姿勢のまま、筋肉を全部 OFF にする。** もし箸が落ちれば、それは筋肉で握っていた証拠。もし落ちなければ——筋肉と無関係に、ただ**指の隙間に幾何的に挟まっていただけ**です。後者を私は**楔 artifact(wedge artifact)**と呼びます。丸い棒は、指のあいだに転がり込むと、力を入れていなくても「挟まって」見える。数値だけ、見た目だけを見ていると、これを「握れた」と誤読します。

実際、初期の「握れた」の多くは楔でした。筋肉を切っても箸が残る——むしろ筋肉 ON のときより長く残ることさえあった。「握力を上げた」と思っていた操作が、本物の握りを一つも作っていなかった。

そこで AI は **4 つのゲート**で判定する検証ハーネスを組みました。**A**=筋肉を切ったら遠くへ落ちるか(手放しの確認)/ **B**=一定時間しっかり保持できるか / **C**=どの向きに押されても押し返せるか(force-closure)/ **D**=揺すられても耐えるか。そして——**この検証ハーネス自身が、最初はバグっていました**。25 体の検証エージェントを敵対的にぶつけて第 1 版をレビューさせると、6 つの欠陥が見つかった。中には**私自身が書いた、揺すり(D)のときの回転を、座標系を取り違えて測っていたバグ**もありました。**測る道具を、まず疑う。** 検証器を検証してから、champion(最良個体)を測り直したのです。

```python
# ablation = 握り姿勢のまま筋肉を全部 OFF にして、落ちるかを見る
run(act = champion_activations)          # ON:  進化で得た筋活性。握れているはず
run(act = np.zeros_like(champion_activations))  # OFF: ここで落ちれば「筋肉で握っていた」証拠
# 落ちなければ = 幾何の楔(wedge)。この手では筋 OFF で 147cm 落下 = 決定的に本物
```

![開ループでは持てず、閉ループにして決まった持ち方。接触部位を点数にするだけでは悪化した(落下 0.21 → 1.12 cm)。フィードバックを入れて落下 0.00 cm へ](https://raw.githubusercontent.com/furuse-kazufumi/fullsense/main/docs/articles/assets/hillco_walk/chop2_closed_loop.gif?v=1)

> 教訓: **ablation は、自分の楽観を殺すいちばん安い道具**だ。切って落ちなければ、それは握れていない。そして、判定する道具そのものにもバグは宿る。

## 5. 二点つまみ — 「正しい形」は、報酬でなく“揺さぶり”から生まれた

楔を弾く物差しができた。では、本物の握りは作れるのか。ここで、私が予想しなかったことが起きました。

正しい箸の持ち方は、**親指の先と人差し指の先の二点でつまむ**形です。私はこの形を作ろうと、報酬(適応度)をあれこれ設計しました——「二点で触れたら加点」「人差し指を接触姿勢に保ったら加点」。**どれも失敗**しました。学習は報酬の抜け道を見つけ、一点で押さえる横着な握りに落ち着く。

効いたのは、報酬ではなく**揺さぶり**でした。「**多少ランダムに突かれても落とすな**」という圧(摂動ロバスト性)を掛けて進化させると、その副産物として、**誰も設計できなかった二点つまみが自然に立った**のです。理屈は後から分かります——一点で押さえる握りは、横から突かれると崩れる。二点で挟む握りは、突かれても持ちこたえる。だから「突かれても耐えろ」と言うだけで、正しい形が選ばれた。

この champion(`best_hold_robust_long`)を、私は今日もう一度回して確かめました(この記事のために再検証)。数値は**当時のまま再現**しました:

- 8 秒の静的保持ゲート **PASS**(落下 0.00 cm・保持中のずれ 2.6 mm)。
- **接触の内訳 = 親指先 37% / 人差し指先 53%**——狙いどおりの二点つまみ。
- **訓練に一度も使っていない揺さぶり**(seed 10〜29、σ=0.02 と 0.05)で、**20 回中 20 回とも回復**。揺れの中央値は 2.6 mm。
- 筋肉を全部 OFF にすると **147 cm 落下**——ablation を決定的に通過。楔ではない。

対照として、揺さぶり圧を掛けずに育てた別の握りは、親指 70% / 人差し指 0% の**一点寄り**で、同じ揺さぶりでは 20 回中 17 回、11 回しか耐えられず、最悪で 1.6 m 崩れ落ちました。**二点つまみが、汎化する頑健さの正体**だったのです。

![接触の設定を直したあとの保持。「持ち方の完成」は最初 1.5 秒窓の見せかけ(artifact)だった。真因は摩擦の次元設定(condim)で、直したら保持が伸びた](https://raw.githubusercontent.com/furuse-kazufumi/fullsense/main/docs/articles/assets/hillco_walk/chop3_hold8s.gif?v=1)

正直な但し書きも残します。この頑健さには**窓の癖(window artifact)**がありました——8 秒でロバストな個体が 12 秒では崩れ、逆に 12 秒安定な個体は揺さぶりに脆い、という具合に。「頑健 **かつ** 長時間」を両立させるには、両方を別々の窓で評価して再進化させる一手間が要った。良い数字だけ見て「完成」と言わない。**どの窓で、どの条件で成り立つのかまで書く**のが、この物差しの作法です。

## 6. 掴めた…と思ったら、皿の重さを握力と読み違えていた

MyoHand で「静的に握る」は本物になった。次は evis で、**皿の上の食べ物を挟んで、持ち上げて、口へ運ぶ**——つまり本当の「食事」です。ここから、正直さの試練が連続します。

一つ、先に正直に置きます。MyoHand で確立した握りは、**evis へそのままは移りません**。手技(どの筋をどう使うか)は移植できても、握りは**その環境に特異的**で、モデルや腕や皿が変わると、そのままでは合成(compose)しない。だから evis では、多くをやり直すことになりました。

最初の「掴めた」は、**測定の誤り**でした。私は接触力を「握力」として読んでいた。ところが食べ物は皿に載っている。**箸だけの接触に絞って測り直すと、力は 0.00 N、接触点は 0**——つまり**箸は食べ物に一度も触れていなかった**のです。私が「握力 0.4 N で保持」と喜んでいた値は、**皿が食べ物を下から支える反力=食べ物の自重そのもの**でした。「持ち上がった +3〜8 mm」も、箸が持ち上げたのではなかった。

同じ誤りは形を変えて何度も出ます。だから私は鉄則を一つ立てました——**接触力は必ず「どの物体との接触か」で絞る**。皿の反力を握力と呼ばない。自重を成果と呼ばない。

```python
# 接触力は「誰との接触か」で必ず絞る
F_all  = contact_force(morsel, ANY)              # 皿の反力(=自重)まで拾う ← 誤り
F_chop = contact_force(morsel, chopsticks_only)  # 箸との接触だけ ← これが本当の握力
# 絞って測り直すと F_chop = 0.00N・接触点 0 = 箸は食べ物に一度も触れていなかった
```

では、正しく測ると何が起きているのか。食べ物を箸先に置いて挟むと、**飛ぶ**のです。落ちるのではなく、**横へ射出される**。実測すると、置いた瞬間に既に箸が食べ物へ**めり込んでいて**(接触力が自重の 10〜90 倍)、そこから加速度的に押し出されていました。上下から圧迫された立方体は、横の拘束が無ければ横へ逃げる——**石鹸を強く握ると、手からピュッと飛ぶのと同じ**です。ロッドの隙間・符号・食べ物の大きさ・皿の高さ、どれを振っても「横へ 5 cm 前後」が動かなかったのは、この機序が支配していたからでした。

![全身で食事をしようとして、掴めない。記録に残る掃引だけで数千回、掴めたと厳密判定できたものは無かった](https://raw.githubusercontent.com/furuse-kazufumi/fullsense/main/docs/articles/assets/hillco_walk/chop5_eat_fail.gif?v=1)

数字で正直に置きます。手元に残っている食事の掃引ログを全部数えると、**設定 73 種・記録 3,168 回**(手作業の掃引に加え、課金ゼロの自動探索を含む)——その**すべてで「掴めた」ゲートは一度も通っていません**。掴めていないものを、掴めたと言わない。この 0 が、この章の成果です。

## 7. なぜ掴めないかを、推測でなく実測で切り分ける

「掴めない」で止まるのは簡単です。難しいのは、**なぜ**を推測でなく実測で言うことです。AI は 3 つの容疑を、一つずつ潰しました。

- **容疑①「箸先の隙間が食べ物に合っていない」→ 反証**。隙間を掃引しても結果は変わらなかった。
- **容疑②「ヒンジ(蝶番)の符号が逆」→ 反証**。符号は直したが、結果は変わらなかった。
- **真因(幾何の破綻)**。箸先の顎の隙間を 5.85 mm に設計したのに、ロッドの半径が 3.2 mm。**左右の棒の表面が中心軸を越えて交差**し、食べ物が入る隙間が**物理的に存在しなかった**。顎が、顎になっていなかったのです。

もう一つ、厄介な真因がありました。食べ物が**箸に沿って手元へ 20 cm も滑り落ちる**。腕の姿勢をいくら変えても直らない。調べると、**箸の仰角がコードにハードコードされていた**(`fwd[2] = -0.28`、つまり -15.78°)。腕とは無関係に、箸は最初から先を下げて構えていた。傾いた箸の上では、触れた食べ物は坂を転がるように手元へ流れる。ここを**水平(-0.28 → 0)**に切り出して直すと、滑落は **-200 mm から -7 mm** へ消えました。支配的だった失敗が一つ、正体を現して片づいた。

> この章の作法: **「たぶん X が原因」ではなく、「X を、こう測って、こう反証した」**。原因は 3 つ潰して、残った 2 つ(幾何の破綻・仰角)が真犯人だった。

## 8. firm capture — 静止でなら、2 本の箸で本当に掴めた

幾何を直し、仰角を直し、横の逃げを塞ぐ。ここまで積むと、evis は**静止した状態でなら、本当に食べ物を挟める**ようになりました。

決め手は 2 つ。ひとつは、**手を水平にスライドさせて運ぶ発想を捨てて、最初から手を口元へ寄せる**こと(口までの距離が 93 cm → 24 cm に縮む)。もうひとつは、**上下の箸の両方に「受け」を付ける**こと。片側だけだと持ち上げ中に 1 点へ落ちるが、両面を受けにすると 2 点が終端まで残る。

この静止把持を、私は今日もう一度回しました(再検証)。結果は正直に、**部分的な成功**です:

- 掴んだ瞬間の接触は 3 点、握力 0.37 N。
- **終端でも 2 点接触・握力 0.56 N を保ち、「掴めた」ゲートを通過**(食べ物の自重の数十倍の力で、2 点で挟み続けている)。
- ただし——**連続して挟み続けられた時間は約 2.8 秒**。

ここが、正直さの分かれ目です。当時の私の記録には「**6 秒間ずっと挟み続けた**」と書いてありました。ですが、**同じレシピを今日回すと、連続保持は約 2.8 秒**。記録の中でも、すぐ下の行には「持ち上げを足すと 2 秒で崩れる」と書いてある。**「6 秒成立」は、AI(と、それを鵜呑みにしかけた私)の楽観**でした。再実測がそれを正した。掴めているのは本物、でも 6 秒ではなく約 3 秒——**この差を、消さずに書きます**。

もう一つ但し書きを。この握りの閉ループ(接触のフィードバック)は、接触力を**シミュレーションの内部から直接読む「神様視点」の特権情報**で回しています。本物の手には、触覚と視覚しかありません。だからこの「掴めた」は、**特権つきの条件での掴めた**です。この特権を触覚(後述する薬指の荷重 8 割)と両眼視差に置き換えるのが、実機への宿題になります。

![開ループでは持てなかった握りを、閉ループ(接触のフィードバック)で決める。静止でなら 2 点で挟み続けられる](https://raw.githubusercontent.com/furuse-kazufumi/fullsense/main/docs/articles/assets/hillco_walk/chop2_closed_loop.gif?v=2)

## 9. そして壁 — 掴めるのに、運べない

静止でなら掴める。では、持ち上げてみましょう。**その瞬間、崩れます。**

同じ握りに、ごく緩やかな持ち上げ(lift)を足しただけで、約 2 秒後に力が抜け、食べ物が落ちる(**「掴めた」判定は 1 回中 0 回**)。速度を極端に落としても同じ。今日の再検証でも、静止なら 2 点で掴めた(掴めた 1/1)のに、持ち上げると落とした(掴めた 0/1)。**「掴める」と「運べる」のあいだに、はっきりした壁がある**のです。

なぜか。理由は 2 つ、いずれも実測で分かっています。

1. **回転は握りを壊し、並進は壊さない。** 肩や手首を**回して**持ち上げると、その関節を跨いでいる筋肉の張力が変わり、握りが上書きされて崩れる。一方、手の付け根ごと**まっすぐ平行移動**させると、握りの関節角は一切変わらないので保持が生き残る。だから運搬は「回さず、滑らせる」が正解だった。
2. **自由度を 1 つ足すだけで壊れる。** 運搬用の関節をモデルに追加すると、追加したというだけで握りが崩れることがあった(モデルの組み方が変わるため)。動作を足すことと、握りを保つことが、真正面から競合する。

この競合には、以前もっと露骨な形で殴られています。「皿 A から皿 B へ豆を運べた」と一度は喜んだ達成が、**あとで自分でズルと認めた**のです。コードを見ると、運搬先の**皿 B を 5.5 cm 低く置いていた**(`plateB_drop = 0.055`)。理由はコメントに正直に書いてある——「豆は運搬中に約 4 cm 沈むので、皿の天面をそこに合わせる」。**食べ物が落ちる先に、皿のほうを動かしていた**。同じ高さの皿なら、豆は皿 B の天面より下へ沈んで横に落ち、失敗します。数値でも見た目でも「成功」に見えたものを、**皿の高さ一つで自分で格下げした**。

![皿 A から皿 B へ豆を運ぶ。手首を回すと崩れ、手の付け根ごと平行に滑らせて通した——ただし皿 B を下げていた「ズル」も、記録として残す](https://raw.githubusercontent.com/furuse-kazufumi/fullsense/main/docs/articles/assets/hillco_walk/chop4_plate_to_plate.gif?v=1)

これが、この記事の壁の正体です——**持ち方と動作を同時に最適化すると、持ち方が犠牲になる**(共進化, co-adaptation)。掴む筋肉と動かす筋肉が同じだから、動作を良くしようとすると握りが緩む。静的な把持は本物になった。だが「掴んだまま動く」は、まだ越えられていません。

## 10. 箸休め — 両目で、距離を測る

一つだけ、うまくいった寄り道を置きます。食事をするには、食べ物が**どこにあるか**を見なければいけません。片目では、遠近が分からない。そこで evis の頭に、人間と同じ **左右 64 mm 離した 2 つの目**を付けました。

原理は、あなたが指を立てて左右の目で交互に見ると位置がずれる、あの**視差(parallax)**です。左右の像で食べ物がどれだけ横にずれて写るか(視差の画素数)から、距離を逆算できる。実測はこうです(今日の再検証):

- 2 つの目の基線 64.0 mm、画角 60 度。
- 食べ物までの**本当の距離 873.6 mm**。
- 左右像の**視差 29.9 画素 → 推定距離 889.3 mm**。**誤差 +15.8 mm(+1.8%)**。

873.6 mm を 889.3 mm と当てた。**誤差 1.8%**——距離を測る幾何としては、本物です。正直な但し書きは一つだけ:左右像で「同じ点」を対応づけるのに、**「食べ物は緑色」という色の特権を 1 つ使っています**(色で重心を抜いた)。そこだけは手抜きですが、視差から距離を出す計算自体はごまかしていません。目が付いたことで、この手はいつか「見て、掴む」へ繋がれる素地を得ました。

## 11. なぜ「未達」を、こんなに丁寧に書くのか(あなたへの贈り物)

ここまで、成功より失敗のほうがずっと多い記録でした。なぜ消さずに書くのか。理由は、これがあなたの役に立つ形の**贈り物**だと思うからです。

- **映像を必ず見る。** この記事の false success(見せかけの成功)は、ほとんど全部、**数値では合格して見えたのに映像で崩れていた**ものでした。掴み 16 mm で「あと一歩」と出たのに、映像では豆が皿に残っている。数字だけ見ていたら、私は「成功」と報告していた。
- **ablation で、自分の楽観を殺す。** 筋肉を切って落ちなければ、握れていない。楔を握力と呼ばない。
- **接触力は「誰との接触か」で絞る。** 皿の反力を、握力と読み違えない。自重を、成果と読み違えない。
- **良い数字が出たら、まず内訳を疑う。** 「6 秒挟んだ」は、同じレシピを回し直したら 2.8 秒だった。「皿 A→B を運べた」は、皿を 5.5 cm 下げていた。**異常に良い結果は、勝った気になる前に必ず内訳を疑う**——これが、私が自分に課している一番のルールです。
- **タスクの新しさを追わない。** 箸把持も、シミュレーションの人型の手も、先人が到達済みです。私が置く価値は、「同じ正直な物差しで、どこまで嘘を剝がせるか」の側にある。

記録した動画は、達成・未達・**誤りの記録**の 3 つのラベルを付けて、消さずに並べてあります(記事末のギャラリー)。誤りを残すのは、恥ずかしいからではなく、**次に同じ穴に落ちる人(未来の私を含む)への地図**だからです。

## 12. 次回に続く

正直な現在地は、こうです。**手の骨格を直し、二点つまみを本物にし(揺さぶりに 20/20)、静止でなら evis も食べ物を 2 点で掴めた。だが「掴んだまま口へ運ぶ」は、まだ落とす。** 掴めるのに、運べない。

壁の攻め方は、もう見えています——そしてそれは「もっと強い学習」ではありません。

- **掴む筋肉と動かす筋肉を、構造で分ける。** 握りを固定した語彙として持ち、その上で運搬だけを学習する。全部を同時に end-to-end で最適化するから、握りが犠牲になる。
- **横バランスは、接地点の小さな補正で吸収する**(capture point)。倒れそうになったら、足や支点を少しずらして受ける。歩行の記事で当たったのと同じ壁が、ここにもある。
- **触覚を、制御の目にする。** この手では、薬指が握りの荷重の **8 割**を「柱」として支えていることが、触覚センサで実測できました。今は接触力を神様の視点(特権情報)で読んでいますが、これを触覚と両眼視差に置き換えれば、実機へ一歩近づきます。

もし壁を越えられたら、それは「反応の速さ」でも「記憶」でもなく、**握りと動作を分けて持てた**最初の証拠になる。越えられなくても——それはそれで、正直な地図がもう一つ増えるだけです。どちらでも、私は書きます。
